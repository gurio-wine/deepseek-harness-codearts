fix: 对齐 LobsterAI 与参考实现 lobsterai2api 的行为差异

实施后逐条回查一致性，发现并修正 4 处实现层缺陷（均为本插件引入）：

C1 resolveLobsteraiUid 多插了一级 JWT sub 回退
   Go（main.go:297-306）只有四级：user.id → user.userId → user.yid → sha256。
   多这一级会让「服务端 user 字段皆空」的账号在本插件得到 sub、
   在 Go 得到 16 位哈希 —— 同一账号两种 uid，破坏与
   auths/lobsterai-{uid}.json 的对照能力。删除该级（jwtSubject 随之无用，一并删除）。

C2 换号条件过窄：404 / 5xx / client 直接抛给用户
   handler.go:218-243 的 switch 每个分支都以 continue 结尾（含 ErrNotFound
   与 default），注释明写「轮转下一个账号，不直接返回（防雪崩）」。
   原实现只对 hard-credit / soft-rate 换号，且注释里错误地声称
   「Go 对 client 类也不换号」—— 实际 NoteError 之后紧跟的就是 continue。

C3 shouldRotateLobsteraiAccount / isLobsteraiCreditExhausted 是死代码
   两个谓词零调用点，适配器走内联条件，导致「策略声明」与「实际行为」分叉。
   改为适配器真正调用该谓词；删除无调用者的 isLobsteraiCreditExhausted；
   新增 recordsLobsteraiRateLimit 区分「换号」与「记限流徽章」——
   Go 只对真正 Cooldown 的三类写冷却时间（hard-credit / soft-rate / not-found），
   session-dead 走 Disable、default 走 NoteError 都不写。原实现给所有换号
   场景都记徽章，会把 400 请求错误显示成「该模型限流 1 小时」，属虚假信息。

C4 余额未 clamp 负值
   client.go:303-308 与 cmd/credit/main.go:91-96 都有 if v < 0 { return 0 }。
   total 与 expiredTotal 均补 Math.max(0, …)，避免显示「-12.5 积分」。

另修正一处有意分歧，改回与 Go 一致：
- applyLobsteraiRefresh 不再更新 latest_keyfrom（原更新为当前时刻）。
  Go 的 RefreshToken（client.go:137-145）只改 token 与过期时间，
  KeyfromBody 始终回发登录时那一刻。语义上「刷新即活动」更直觉，
  但 Go 是唯一生产验证过的实现，更新它需实测支撑，不能从代码推导。

保留的有意分歧（已在计划文档 §7.4 标注理由）：
- 续期终态判定比 Go 精确（Go 把网络抖动也当终态，会误让用户重新登录）
- version 用动态真值（Go 硬编码假值 0.1.0）
- 不移植自动冷却/禁用状态机（D2；注意「轮转」与「冷却」是两件事，
  本插件采纳轮转、不用冷却）

新增 tests/unit/lobsterai-parity.spec.ts（24 项一致性契约，每条标注 Go 依据位置），
防止后续凭直觉优化造成无声漂移。该文件经反向验证：临时把 C1 加回去，
确认 2 项测试确实失败后再撤回修复。

测试：761 项全绿（+26），build:all 与 typecheck 通过。
